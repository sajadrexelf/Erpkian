# 02 — بافت سیستم و مرزهای تعامل (`System Context — C4 Level 1`)

**نمودار مرجع:** [`diagrams/system-context.mmd`](./diagrams/system-context.mmd)

این سند جایگاه پلتفرم **Erpkian** را در اکوسیستم عملیاتی مشتری، کاربران انسانی، نرم‌افزارهای مبدأ و سرویس‌های بیرونی مشخص می‌کند.

---

## ۱. بازیگران انسانی (`Human Actors`)

مطابق `docs/processing/05-role-permission-matrix.md`، تعامل کاربران از طریق رابط وب واکنش‌گرا (`RTL Web & Mobile Web`) با کنترل دسترسی `Permission-Based` انجام می‌شود:

| گروه کاربری | نقش‌های سیستمی (`roles.code`) | کانال و نیاز اصلی |
| :--- | :--- | :--- |
| **مدیریت ارشد** | `OWNER`, `CEO` | داشبورد لحظه‌ای، گزارش‌های نسخه‌پذیر، تایید دوامضایی بالای سقف، تحلیل مکالمه‌ای |
| **مدیریت مالی** | `CFO`, `SENIOR_ACCOUNTANT` | کنترل دوره مالی، روش ارزش‌گذاری (`FIFO`/`Weighted Avg`)، تایید `Posted`، سودآوری و مالیات |
| **عملیات حسابداری** | `ACCOUNTANT`, `OPERATOR` | آپلود اسناد، OCR Review، مغایرت‌گیری بانکی، ثبت دریافت/پرداخت و تطبیق موجودیت |
| **عملیات فروش و انبار** | `SALES_MANAGER`, `INVENTORY_MANAGER` | گزارش فروش و پیگیری مطالبات (بدون دسترسی به خزانه)، ورود/خروج انبار (بدون رویت سود/قیمت خرید در حالت محدود) |
| **کاربر مستقل** | `PERSONAL_USER` | ثبت ساده اسناد شخصی، کنترل مخارج و حساب‌های شخصی در فضای تک‌نفره |

---

## ۲. نرم‌افزارها و سیستم‌های ورودی مشتری (`Customer-Side Inputs`)

1. **فایل‌های مستقیم کاربر:** تصاویر موبایلی فاکتور و رسید (`JPG`, `PNG`, `HEIC`, `WEBP`)، اسناد اسکن‌شده و گزارش‌های `PDF`، فایل‌های اکسل و CSV صورتحساب بانک و خروجی نرم‌افزارها، و فایل‌های فشرده `ZIP`.
2. **عامل ویندوز محلی (`.NET Windows Agent`):**
   - روی کامپیوتر یا سرور ویندوزی شرکت پخش نصب می‌شود.
   - در **v1 اکیداً `read_only = true`** است (`OD-11`, `CONFIRMED`).
   - داده‌های خروجی یا جدول‌های خواندنی هلو، سپیدار و راهکاران و پوشه‌های مجاز انتخاب‌شده توسط کاربر را به صورت امن (Outbound HTTPS با Device Key تک‌سازمانی) به Erpkian ارسال می‌کند.

---

## ۳. سیستم‌ها و سرویس‌های بیرونی (`External Dependencies`)

| سیستم بیرونی | نقش در Erpkian | وضعیت و محدودیت معماری |
| :--- | :--- | :--- |
| **ارائه‌دهنده مدل زبانی (`LLM Gateway`)** | تشخیص نیت، استخراج تکمیلی ساختاریافته، توضیح فارسی نتایج قطعی | **هرگز** محاسبه ریاضی نمی‌کند؛ خروجی فقط بر پایه اعداد `ErpkianReportEnvelope` است؛ داده‌های هویتی حساس (`IBAN`, `password_hash`) پالایش می‌شوند. |
| **موتورهای OCR / VLM** | تبدیل تصویر/PDF به متن، جدول و مختصات `bbox` | هسته اولیه Self-Hosted (`PaddleOCR` + پیش‌پردازش OpenCV)؛ Vision LLM فقط به عنوان Fallback اختیاری با کنترل هزینه و حریم خصوصی. |
| **فضای ذخیره‌سازی اشیا (`S3 / MinIO`)** | نگهداری فایل اصلی تغییرناپذیر، صفحات پردازش‌شده و خروجی PDF/Excel | دسترسی فقط از طریق Pre-signed URL کوتاه‌عمر (۲ دقیقه) با Prefix سازمانی `<org_id>/<doc_id>/`. |
| **سرویس‌های اعلان (`SMS / Email / Push`)** | ارسال کد ورود/دعوت، هشدار تایید دوامضایی، یادآوری سررسید چک | فراخوانی Async از صف `q.notifications.dispatch` بدون مسدود کردن API. |
| **سامانه مودیان و TTMS 169** | ارسال رسمی صورتحساب الکترونیک و گزارش فصلی | **`LOCKED_IN_V1`** — در نسخه اول فقط پیش‌نویس و اعتبارسنجی شناسه (`TAX-PREP-*`, `TAX-VAL-*`) فعال است؛ ارسال رسمی قفل شده است. |
| **Open Banking مستقیم** | دریافت برخط تراکنش‌های بانکی | **`DEFERRED_TO_FUTURE_PHASE`** — در v1 صورتحساب بانکی از طریق فایل Excel/CSV/PDF وارد می‌شود. |

## ۴. جریان‌های کلان سطح سیستم (`System-Level Flows`)

1. **جریان ورود سند و تبدیل به داده مالی:** `کاربر/Agent -> آپلود به S3 -> پیش‌پردازش و OCR در FastAPI -> راستی‌آزمایی ریاضی در NestJS -> بازبینی انسانی -> دروازه Posting و Dual Approval -> ثبت در PostgreSQL`.
2. **جریان مکالمه‌ای و تحلیلی:** `پرسش کاربر -> Input Sanitizer -> Intent Router -> بررسی RBAC/Branch -> موتور قطعی و Snapshot PostgreSQL -> ErpkianReportEnvelope -> لایه توضیحی LLM -> ویجت‌های UI`.
3. **جریان همگام‌سازی ERP:** `هلو/سپیدار (محلی) -> Windows Agent (Read-Only) -> Ingestion API -> ImportBatch & Row Hash -> Entity Resolution -> نیاز به تایید انسانی در موارد مبهم`.
